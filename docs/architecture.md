# System Architecture

## Overview

Mini-SIEM is a centralized Security Information and Event Management (SIEM) platform designed to collect, analyze, and manage security events generated from various sources. The system provides real-time monitoring, automated threat detection, alert management, incident response capabilities, reporting, and AI-assisted security analysis.

The architecture follows a modular design approach where each component performs a specific function within the security monitoring lifecycle. This design promotes maintainability, scalability and ease of future integration with external security tools.



# Architectural Goals

The architecture was designed to achieve the following objectives:

* Centralized collection of security logs.
* Real-time threat detection and alert generation.
* Automated incident response through host quarantine.
* Security event visualization through a dashboard.
* AI-assisted investigation and alert explanation.
* Report generation for management and auditing purposes.
* Modular structure for future expansion.

# Component Architecture

## 1. Log Collection Layer

### Purpose

The Log Collection Layer serves as the entry point for all security events entering the system.

### Responsibilities

* Receive logs through REST API endpoints.
* Validate incoming log data.
* Normalize log structure.
* Store logs in the database.
* Forward events to the detection engine.

### Main Endpoint

POST /submit-log


### Example Collected Events

* Failed login attempts
* Successful logins
* Port scans
* Suspicious network activity
* Application security events
* Malware detections


# 2. Security Data Repository

### Purpose

The repository acts as the central storage component of the SIEM platform.

### Stored Information

#### Logs

Raw security events collected from monitored systems.

Examples:

* Source IP
* Event type
* Severity
* Timestamp
* Event details

#### Alerts

Security incidents generated by the detection engine.

Examples:

* Brute force attack detected
* Port scan detected
* Excessive authentication failures

#### Quarantine Records

Information about isolated hosts.

Examples:

* Host IP
* Quarantine timestamp
* Status
* Release timestamp

### Benefits

* Historical analysis
* Forensic investigations
* Reporting
* AI context generation



# 3. Detection Engine

### Purpose

The Detection Engine is responsible for identifying suspicious activities based on predefined rules.

### Detection Workflow


Incoming Log
      |
      v
Rule Evaluation
      |
      v
Threat Identified?
      |
   Yes/No
      |
      v
Generate Alert
      |
      v
Store Alert


### Implemented Detection Rules

#### Brute Force Detection

Conditions:

* Multiple failed login attempts.
* Repeated attempts from the same source.
* Configurable threshold.

Generated Alert:


"Potential Brute Force Attack"


#### Port Scan Detection

Conditions:

* Multiple connection attempts.
* Large number of destination ports.
* Short observation period.

Generated Alert:


"Port Scanning Activity Detected"


### Alert Severity Levels

* Low
* Medium
* High
* Critical



# 4. Response Engine

### Purpose

The Response Engine performs containment actions after security incidents are detected.

### Current Functionality

#### Host Quarantine

The system can automatically quarantine suspicious hosts.

Process:


Alert Generated
      |
      v
Host Identified
      |
      v
Quarantine Action
      |
      v
Host Added To Quarantine List


#### Host Release

Administrators can release quarantined hosts after investigation.

### Benefits

* Rapid incident containment.
* Reduced attack propagation.
* Demonstration of automated incident response.



# 5. Notification System

### Purpose

Provide immediate awareness of security incidents.

### Features

* Email alerts.
* Telegram message and voice alerts
* SMS alert for offline purposes
* IVR for immidiate action
* Incident notifications.
* Security summaries.

### Notification Flow


Alert Generated
      |
      v
Email Service
      |
      v
Security Analyst




# 6. AI Analysis Module

### Purpose

Provide intelligent assistance for security investigations.

### Components

#### Context Builder

Collects relevant information from:

* Recent alerts
* Recent logs
* Quarantine records
* Security statistics

#### AI Chat Interface

Allows users to ask security-related questions using natural language.

Examples:


"What are the most recent alerts?"

"How many failed logins occurred today?"

"Explain alert 15"

#### Alert Explanation

The AI module can analyze alert details and provide:

* Incident summary
* Potential causes
* Impact assessment
* Recommended actions

### Advantages

* Faster investigations.
* Reduced analyst workload.
* Improved situational awareness.



# 7. Reporting Module

### Purpose

Generate security reports for operational and management purposes.

### Report Contents

* Total logs collected
* Alerts generated
* Alert severity distribution
* Top attackers
* Quarantine statistics
* Security recommendations

### Export Formats

* PDF reports
* Dashboard summaries
